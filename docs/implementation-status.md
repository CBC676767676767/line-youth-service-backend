# 系統實作狀態與驗證邊界

更新日期：2026-09-19。此文件描述儲存庫內已實作的內容；原計畫書與規格書仍是規劃基準，不能把其全部功能、服務水準或驗收目標視為已交付。

## 目前可操作的內容

| 領域 | 實作狀態 | 邊界 |
| --- | --- | --- |
| 帳號 | 信箱 OTP、Cookie、CSRF、工作階段撤銷、密碼＋TOTP MFA、LINE token 驗證與綁定 | 信箱與 LINE 只證明帳號控制；不代表實名認證 |
| 申請 | 單一固定方案、草稿、欄位驗證、正式提交、版本及回執、冪等查詢 | 保留開發方案，新增新竹市青年 AI 補助固定表單與必要文件檢查；沒有通用表單設計器或完整表單版本遷移工具 |
| 補件 | 建立、修訂、期限、提交、退回、接受與取消；原回執保留 | 期限規則與展延政策仍需主辦定案；不自動推定法定期限 |
| 審查 | 逐案權限、檢核與證據、主管決定、更正、結案；管理員無預設文件全文權限 | 已提供程式控制，尚未完成機關正式權限及分工核定 |
| 附件 | 20 MiB／檔、正式提交最多 10 檔、magic type 檢查、create-only 私有物件、隔離狀態與授權串流 | 開發格式檢查不是防毒；PDF 預覽以附件下載，Range 明確不支援 |
| 通知 | 業務交易 Outbox、租約接手、同 retry key／payload、有限重試、站內通知與查看紀錄 | 沒有 LINE 憑證不會假報接受；尚未實接真實官方帳號 |
| Webhook | 原始本文 HMAC、destination 檢查、DB 去重、Inbox 持久化、follow／unfollow 亂序處理 | 已有自動化測試，尚需真實 Channel 驗證與上線觀測 |
| 管理與匯出 | 帳號停用、受限制角色調整、認領受理、稽核、彙整與受控 CSV 匯出 | 高權限新授予／擴大由 API guard 阻擋；完整雙人核准流程尚未建置 |
| 執行環境 | PostgreSQL 17、Alembic、原生 API／worker、Docker image 及 Compose profile | 尚未建置正式高可用架構或機關部署環境 |

掃描與正式提交分開：文件完成持久化後，可在等待掃描時建立回執；掃描或承辦確認不改寫原收件時間。只有 CLEAN 文件可下載、接受或用於必要審查。原件與正式提交不可覆寫，文件替代必須保有明確來源及審查證據。

替代證據使用 `file_version_id` 指向新文件 B、`replaces_file_version_id` 指向舊文件 A，並附 `rule_version_id` 與 `note`。B 必須是同案、同文件類別、已接受補件中的 CLEAN 文件，不能單憑新增一份上傳就略過原始文件問題；決定保留替代關係及文件雜湊，原回執不變。

通知排程支援 `scheduled_at`；目前沒有硬編某一機關的催件頻率。過期要求、已提交任務、撤銷綁定等情況會依最新狀態略過或取消待發工作。LINE 的 `API_ACCEPTED` 不表示送達或已讀；IN_APP 的同名狀態僅表示站內通知發布。

## 啟動與資料位置

操作命令見 [README](../README.md)。原生模式使用 `.env` 中的 PostgreSQL 連線與本機 `var` 目錄；容器 API／worker 共用 `/data` named volume。兩種模式不能在不同儲存目錄下共用同一批文件紀錄。金鑰、工作階段、驗證郵件及附件皆不屬於 Git 交付物。

## 網站整合更新

民眾 `/` 與管理 `/admin/` 使用獨立 HTML/React 入口，共用同源 API。申請人透過信箱驗證，工作帳號保留密碼與 TOTP；前端不提供角色切換，瀏覽器重新整理後由 `/me` 和案件 API 還原。未儲存的 OCR 全字號與原始文字不會寫入 web storage；申請表僅保留遮罩字號，附件需使用者另行選擇上傳。

方案 `hsinchu-ai-grant-2026` 使用固定白名單欄位及條件文件要求，原 `youth-demo` 不變。文件依一次性 intent／PUT／complete 完成私有儲存後加入回執；送件重試保留同一識別碼與內容，承辦變更帶版本與證據。管理端只列正式提交的文件版本。

本次未增加核銷／匯款狀態或真實出納整合；未聲稱 OCR 能驗證證件真偽，也未量測真實照片辨識準確率。

網站整合驗證：Python 回歸 140 項與前端 32 項測試通過，兩個入口 TypeScript／Vite 建置通過。新增隔離真 HTTP 流程驗證信箱與工作帳號登入、六類附件、補件、安全掃描前阻擋接受、人工證據與核定；步驟見 [整合驗證](web-smoke.md)。遠端 CI 的實際結果請查看 GitHub Actions。
